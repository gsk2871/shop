# 首页轮播与进站留资

## 功能

后台「Banner管理」的首页主视觉使用后台名称、电脑图片、手机图片（选填）、关联商品（选填）、排序与启用状态。名称只用于管理，不展示给访客；无需替代文本配置。首页固定按钮文案为 `Shop Now`。链接由后端根据关联商品生成，只有未删除、已发布并具有有效价格 SKU 的商品显示按钮。没有关联或商品不可访问时仍显示图片。其他投放位保留原有标题、副标题、链接、按钮和排期功能。

首页多张图每 5 秒轮播，支持圆点、左右切换及触摸横滑。鼠标悬停、键盘聚焦和系统减少动态效果设置会暂停自动播放。单图不显示切换控件；无图隐藏区域。建议电脑图 1920×720、手机图 800×1000，在底部居中预留按钮区域。

后台「系统配置 → 留资弹窗配置」管理开关、主标题、说明、输入框提示、提交及拒绝按钮文字、底部说明、成功标题和说明。英文种子采用 10% 优惠示例，默认启用，具体文本以 `backend/internal/biz/leads/leads.go` 的 `Default` 为准。种子重复执行不覆盖人工修改。优惠由人工跟进确认，不包含自动发券或消息发送。

弹窗挂载在官网根布局，任意页面直接进入均可展示。一次访问按当前标签页的浏览器会话计算，使用 `sessionStorage` 记录已展示状态；刷新、站内导航不重复弹出，不使用 30 天免打扰标记。关闭标签页后的新会话重新展示；浏览器恢复会话可能保留会话存储。浏览器禁用存储时只能保证同一文档内不重复，重新加载仍会展示。点击弹窗外侧遮罩空白、关闭按钮、拒绝按钮和 Escape 均可退出；点击弹窗内部（含留白）或从内部拖动至外侧不会关闭；原生 modal dialog 提供焦点约束。

联系方式为单输入框，支持邮箱或包含国家区号的 WhatsApp。邮箱按小写规范化，号码移除空格、横杠和括号。格式校验不验证邮箱或号码所有权，也不验证 WhatsApp 是否注册。

「运营管理 → 留资记录」显示类型、联系方式、首次/最近提交时间、次数、状态及备注。筛选项只有联系方式和提交起止时间，按最近提交时间过滤。筛选器使用浏览器本地时间，列表显示北京时间。状态仅为待跟进、已完成、无效。同一联系方式重复提交采用数据库唯一约束和原子更新：保留首次时间、备注，更新最近时间和次数，恢复待跟进。修改状态及备注使用版本号，发生并发变更时要求刷新。

不收集来源页面、广告参数；访客 IP 仅在进程内短期用于限流，不写入留资表。

## API 与权限

| 接口 | 用途 | 权限 |
|---|---|---|
| GET /api/v1/lead-popup | 公开弹窗配置，不返回版本号 | 公开 |
| POST /api/v1/leads | 提交联系方式，只返回成功标记 | 受信任官网代理 |
| GET /admin/api/v1/banner-products | 搜索可访问商品，仅返回 ID 与名称，最多 20 条 | banner.read |
| GET /admin/api/v1/lead-popup | 后台配置 | lead_popup.read |
| PUT /admin/api/v1/lead-popup | 保存配置 | lead_popup.update |
| GET /admin/api/v1/leads | 分页查询，contact/start/end/page/pageSize | lead.read |
| PATCH /admin/api/v1/leads/{id} | 更新 status/note/expectedVersion | lead.update |

沿用已有后台认证、跨站请求防护和操作审计。初始超管、内容管理员获得新增权限；默认只读角色不获得联系方式读取权限。升级时已有普通角色授权保持不变，需要超管显式授予新增菜单及操作权限。

本项目当前是每个部署使用独立数据库的单站点结构，本次延续此隔离边界，没有新增共享数据库多租户模型。

公开提交通过官网 `/api/leads` 转发，拒绝跨站来源与非 JSON 请求，仅转发联系方式和受信任 IP，不转发 Cookie。官网读取正文限 4 KiB、5 秒；后端 JSON 解码限 16 KiB并拒绝未知字段。后端仅信任 `auth.trusted_proxies` 中的网络对端，通过专用 `X-Client-IP` 获取访客地址。沿用现有 Nginx/开发入口覆盖该请求头的部署方式，Next 和后端不应绕过入口公开暴露。

限流为单后端进程每 IP 10 分钟 5 次、全局每分钟 60 次，内存映射最多 4096 项并清理过期项。热加载不会清空计数，进程重启会重置；多实例部署需改为共享限流状态。配置关闭后不再接收提交。

## 升级

1. 备份数据库，按既有部署流程构建三端。
2. 执行 `backend` 服务的 `-migrate`，应用 `000006_banner_leads.up.sql`，新增 Banner 商品关联、`lead_popup_config` 和 `contact_lead`。
3. 执行 `-seed`，更新权限和缺失的英文弹窗配置。未执行种子时弹窗保持关闭，后台提示初始化。
4. 同步发布后端、后台和官网。检查普通角色授权并确认弹窗文案。
5. 现有首页图片会转为整图展示，旧标题/副标题不再对外显示，旧自由链接不再使用；需要在后台关联商品后才显示按钮。首页不再使用排期，仅依据启用状态；升级前检查原有首页投放是否需要停用。

回滚迁移会删除留资数据及配置，不能作为无损回滚手段。
